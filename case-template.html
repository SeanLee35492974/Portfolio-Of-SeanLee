01 / Project Overview

先给读者一张项目地图。

用一段话交代项目名称、业务背景、你的角色、时间范围、工作范围和最终想解决的问题。

Role你在项目中的实际角色
Time项目时间与阶段
Output最重要的交付物
02 / Context

项目为什么发生？

交代触发项目的业务背景、组织需求和现实场景。

尽量说明是谁遇到了什么问题，为什么此时要做，以及你的工作从哪里开始。不要先急着写成果，让读者先建立理解坐标。

03 / What I Found

你真正看到了什么？

01 / SIGNAL现象：表面上发生了什么？
02 / FRICTION阻力：哪里让理解、参与或执行变慢？
03 / FOCUS重点：这次项目先解决什么，不解决什么？
04 / What I Did

你真正做了什么？

按照时间或逻辑顺序，写清楚判断如何转化成行动。

01

理解与梳理

信息、对象、场景与优先级。

02

策划与转译

主题、结构、内容与传播路径。

03

制作与表达

文案、视觉、视频或页面落地。

04

协同与交付

评审、修改、发布与后续沉淀。

05 / Constraints

哪些事情暂时不能做？

把预算、时间、权限、系统、协作和信息边界说清楚，限制本身也是项目判断的一部分。

现实条件预算、时间、系统、权限或协作边界。
应对判断在当前条件下先做什么，哪些问题留到下一阶段。
06 / Design Principle

这个项目坚持的表达原则。

精确内容准确，判断清楚。
简洁让重点更容易被理解。
克制形式服务于内容与场景。
07 / Shipped

最后留下了什么？

交付物 + 影响范围 + 沉淀机制

如果暂时没有硬数据，就具体说明做成了什么、覆盖了谁、为下一次工作留下了什么。

08 / Concept Redesign

如果拥有更多权限，还可以怎么做？

概念重设计不是虚构已经完成的成果，而是把前面发现的问题，转化为下一阶段可以被讨论的方向。

01

方向一

基于项目实际问题，提出一个更完整的设计方向。

02

方向二

说明它如何改善理解、参与或执行。

09 / Reflection

这个项目改变了什么认识？

回到项目本身，写清楚你学到了什么，如果重新推进会怎样做，以及这段经验如何影响下一次判断。
